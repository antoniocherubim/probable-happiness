# PC-03 — Fluxo pessoal ponta a ponta

Status: concluída.

Objetivo único: provar execução, review, decisão humana opcional, resume e
verificação de snapshot sem qualquer operação Git remota.

Telegram é adaptador; o fluxo local deve funcionar quando ele estiver
desabilitado ou indisponível.

## Escopo

- adicionar `approval.mode = "none" | "telegram"` ao perfil estrito;
- finalizar `APPROVED` localmente somente depois de congelar e verificar o
  manifesto revisado quando o modo for `none`;
- preservar o gate e a retomada atuais quando o modo for `telegram`;
- impedir transportes Git remotos em toda fase supervisionada;
- provar o caminho completo com scopes `systemd --user` reais.

O default permanece `telegram` para compatibilidade. O modo `none` não cria
request nem outbox Telegram. Indisponibilidade do adaptador no modo `telegram`
mantém `AWAITING_HUMAN_APPROVAL` e pode ser retomada sem promover estado.

## Critérios de aceite

1. execução, mudança, validação e review `APPROVED` completam sem Telegram;
2. `verify` e `resume` revalidam o mesmo hash e detectam drift;
3. executor e reviewer não conseguem abrir transporte Git HTTPS/SSH;
4. o gate Telegram existente continua coberto;
5. os gates reais de sinal, timeout e limites da PC-02 continuam sem processos
   sobreviventes;
6. nenhuma etapa executa commit, push, fetch, pull ou outra publicação.

## Evidência

- `venv/bin/python -m pytest -q`: **211 passed**, sem skips;
- o E2E real executou Cursor falso, mudança, validação, Codex falso, aceite
  técnico, `verify` e `resume` em scopes `systemd --user`;
- tentativas HTTPS no executor e SSH no reviewer falharam com
  `transport ... not allowed`;
- os gates reais de sucesso, erro, sinal, timeout e cotas confirmaram a remoção
  dos descendentes, inclusive os que abriram nova sessão;
- `systemctl --user list-units 'agent-loop-*.scope' --all --no-legend` terminou
  vazio após a suíte.

## Riscos residuais

- `GIT_ALLOW_PROTOCOL=file` bloqueia transportes do Git, não clientes genéricos
  como `curl`;
- repositórios deliberadamente hostis e adulteração pelo mesmo UID continuam
  fora do modelo de confiança;
- Telegram mantém entrega *at-least-once* e exclusividade operacional da ponte,
  sem afetar o caminho `none`.
