# DX-08A2 — Diretório seguro para status e heartbeat

Status: planejada.

Base obrigatória: resultado aprovado da DX-08A1.

## Contexto

O review 7 da DX-08A reproduziu `read_status()` e publicação de heartbeat por
um caminho contendo symlink intermediário e também dentro de um run directory
em modo `0755`.

## Objetivo único

Garantir que leitura de status e publicação de heartbeat operem somente em um
run directory canônico, privado e pertencente ao usuário esperado, encerrando
e coletando o processo supervisionado se essa garantia deixar de valer.

## Escopo obrigatório

1. Validar sem reparo todos os componentes do caminho do run directory:
   nenhum symlink intermediário ou final, diretório regular, owner esperado e
   modo privado `0700`.
2. Aplicar a validação em `read_state()`/`read_status()` e antes da publicação
   de `heartbeat.json`.
3. Publicar heartbeat pela API segura comum, com containment no run directory,
   arquivo `0600` e sem seguir links.
4. Se a validação ou publicação falhar durante a supervisão, terminar o grupo
   do processo, aguardar sua coleta e propagar o erro sem publicar heartbeat
   ou outro sucesso.
5. Ajustar `ROADMAP.md` e esta task somente com essa garantia específica;
   DX-08 e M1 continuam abertos.

## Limite de mudança

Arquivos de produção permitidos:

- `scripts/agents/dx/persist.py`;
- `scripts/agents/dx/state_machine.py`;
- `scripts/agents/dx/runtime.py`.

Testes em `tests/unit/test_agent_dx08a.py` e documentação citada acima.
Não alterar reports, iteration budget, transactions, migration ou rollback.
Não fazer refatorações adjacentes.

## Critérios de aceite

1. Symlink intermediário/final, run directory `0755` e owner inesperado falham
   antes de leitura ou publicação persistente.
2. Alteração insegura ocorrida após o spawn encerra e coleta o grupo filho.
3. Nenhum heartbeat ou artefato de sucesso é criado na recusa.
4. O fluxo normal em diretório `0700` continua funcional.
5. A suíte completa e as validações estáticas passam.

## Testes obrigatórios

- status e heartbeat por symlink intermediário e final;
- run directory `0755` e owner inesperado;
- falha introduzida após spawn, comprovando TERM/KILL quando necessário,
  `wait()` e ausência de filho sobrevivente;
- snapshot byte-a-byte dos diretórios real e alias antes/depois da recusa;
- fluxo válido em diretório `0700`;
- `pytest tests/unit`;
- `python3 -m compileall -q scripts/agents/dx`;
- `bash -n` nos scripts shell;
- `git diff --check`.

## Fora de escopo

Todo finding que não pertença diretamente a status, heartbeat ou cleanup do
processo supervisionado. Finding novo deve ser reportado para uma task
posterior, não incorporado aqui.
